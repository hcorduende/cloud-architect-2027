# Program Operating Model

**Weekly capacity:** 12 hours  
**Program start:** 1 December 2026  
**Working principle:** one primary technical track at a time, with small transversal practice.

## Suggested weekly allocation

| Activity | Hours | Output |
|---|---:|---|
| Primary track / certification objective | 6 | Lab, implementation or exam-domain evidence |
| Python / automation | 2 | Small tool, script or test |
| Architecture and security | 1.5 | Diagram, ADR, threat model or design review |
| English for technical work | 1 | Read, explain or present one technical topic |
| Documentation and weekly review | 1.5 | README updates, sanitized evidence, next sprint |
| **Total** | **12** | |

The split is a default, not a rigid rule. In the AZ-104 exam month, the six-hour primary block prioritizes Azure administration and practice exams. Before a practical lab, move time toward prerequisites and safe implementation. Do not study all tracks deeply every week.

## Definition of done

A learning item is complete only when:
1. The concept can be explained without reading the notes.
2. A lab, test, diagram or written design demonstrates the skill.
3. The result has been validated and limitations are documented.
4. Security, cost and cleanup have been considered.
5. The evidence is committed without secrets or confidential data.

## Sprint rhythm

- **Plan:** choose one outcome for the week and break it into small tasks in Trello.
- **Build:** perform the lab locally or in an isolated sandbox.
- **Prove:** run tests/validation and capture sanitized evidence.
- **Publish:** commit focused changes and link the evidence in Notion.
- **Review:** record actual hours, blockers and the next most valuable step.

## Tool responsibilities

- **Notion:** source of truth for roadmap, objectives, dependencies and certification dates.
- **Trello:** active work, weekly sprint, blockers and done items.
- **GitHub:** versioned code, labs, architecture decisions and public evidence.
- **Obsidian:** personal technical notes, concept maps and study explanations.

Avoid copying entire bodies of knowledge across tools. Link to the canonical item instead.
