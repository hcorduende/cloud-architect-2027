# Contributing

This is a personal learning and portfolio project. Changes should improve reproducibility, correctness, security or clarity.

## Workflow
1. Use a focused branch: `feat/<topic>`, `fix/<topic>`, `lab/<topic>` or `docs/<topic>`.
2. Keep changes small and explain the motivation in the commit.
3. Validate commands, code and links before merging.
4. Update lab status only when the milestone is genuinely complete.

## Lab checklist
- [ ] Objective and prerequisites are stated.
- [ ] Architecture and data flow are understandable.
- [ ] Steps are reproducible from a clean environment.
- [ ] Validation and expected results are included.
- [ ] Cost and cleanup are addressed.
- [ ] Security risks and limitations are documented.
- [ ] No secrets or employer-confidential information are included.

## Commit style
Use prefixes where practical: `docs:`, `feat:`, `fix:`, `test:`, `security:`, `refactor:`.
